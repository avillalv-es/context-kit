What was measured, and how hard the number is

Two layers, and they are not equally strong. The deterministic layer is exact and re-runnable: it counts the bytes of project context each layout forces a session to load. The empirical layer runs a real model on real tasks, and at three repetitions per cell it can only tell you whether an effect is large enough to be obvious.

Both arms are generated from the same blocks/ directory, so they hold identical facts by construction. verify-parity.sh asserts it at every size, and it passes.

The other side of the same number

This is the honest risk. Withholding 81–94% of the project’s written knowledge is the mechanism by which the saving happens. It is only a good trade if the routing is right. A rule whose paths: glob misses the file being edited is a fact silently withheld, and nothing in the layout will tell you it happened.

The empirical result

Median peak context was 66.7k for the tiered layout against 85.3k for the single file — 22% lower, across 5 and 4 runs. Spread was 51.7k–67.6k and 68.3k–91.0k.

Most of both bars is not the layout. Roughly 51.7k of every run is fixed overhead — system prompt, harness, tool schemas — paid identically by both arms. Measured against only the part a layout can move, the gap is 15.1k against 33.6k. The percentage above is the honest whole-window figure; this is the honest mechanism figure. Neither is a benchmark at N=9.

Method, and what it does not support

Design

  • Both arms are generated from one blocks/ directory, so they hold the same facts by construction. verify-parity.sh asserts it and passes at all three sizes.
  • Prompts are identical except the directory. Neither agent was told an experiment was running, or which arm it was in.
  • Each of the 24 runs got its own clean working copy.
  • context-kit’s hook-injected ruleset fired for both arms, identically. It is a constant and cannot explain any gap between them.
  • Empirical numbers come from the subagent transcripts, not from context-kit’s own activity ledger. The ledger only sees the file-reading tool, and these agents read through cat and grep far more often, so the ledger undercounts by a wide margin. peak is input + cache_creation + cache_read at its maximum over a run — the largest the context window actually got.

What this cannot tell you

  • Three repetitions per cell. Enough to notice a large effect, nowhere near enough to measure a small one, and not a benchmark.
  • One project, one model, one session. The project was written for this test, which means its knowledge is unusually well-organised into areas — exactly the condition the tiered layout is best at. A repo whose conventions cut across areas would route worse.
  • The deterministic layer counts what a layout forces a session to load, not what a model chooses to read. An agent that reads the whole repo anyway defeats the layout, and nothing here prevents that.
  • knowledge/ is counted as zero for the tiered arm. That is the model’s claim, and it is the single assumption most likely to flatter it.

Reproducing it

Everything is in ab/: measure-static.sh for the exact numbers, verify-parity.sh for the fairness check, factgap.sh for the withheld-facts count, grade.sh for correctness, collect-tokens.py for the per-run telemetry, report.py to rebuild these charts. The raw TSVs every figure is drawn from are in ab/results/.
